# LYNX Imager 三工作区设计需求包

> 2026-11-24 UI 约束重置：本目录的旧视觉稿、布局、配色、尺寸和页面组织方案仅作历史参考，不限制新页面设计。设备操作、权限与后端安全语义仍按实际业务实现保留。

## 文档用途

这是一套面向产品、交互、前端、后端编排和测试人员的设计需求。它定义 LYNX Imager 的三种工作区、烧录主流程、AI 接入方式、状态表达和验收规则。

本包是设计与需求资料，不是代码实现，也不代表效果图中的示例设备、文件、端口或状态已经在实机验证。

## 核心定位

LYNX Imager 面向两类使用者：

- 普通用户：快速、清楚地把适配的系统镜像写入开发板。
- 专业用户：查看并配置现有烧录路线、Loader、存储和执行参数。

软件分为三个工作区：

| 工作区 | 默认对象 | 主要目标 |
|---|---|---|
| 基础烧录 | 普通用户 | 用四步完成系统写入 |
| 高级烧录 | 开发者、调试人员 | 集中配置并运行预检 |
| 连接 AI | AI 工具使用者 | 配置 MCP 并管理调用确认 |

## 主流程

```mermaid
flowchart LR
    A[基础烧录] --> B[选择板子]
    B --> C[选择系统]
    C --> D[配置接口]
    D --> E[只读预检]
    E --> F[确认烧录抽屉]
    F --> G[烧写系统]
    G --> H[写入结果]
    H --> I[人工或串口确认启动]
```

## 设计原则

1. 基础流程只在当前步骤展示当前需要的信息。
2. 高级功能提供更多控制，但不能绕过现有安全保护。
3. AI 是调用通道，不是另一套烧录后端。
4. 写入、校验、重启和系统启动始终分开报告。
5. 示例状态不能伪装成真实硬件验证结果。
